## 3. Механика базовой игры

Обычный 25-линейный слот. Единственный усилитель базы — стакнутые вайлды на всю колонку.

Над барабанами стоят **три плетёные корзины** (слева направо):

| Горшок | Ярлык в UI | Внутренний код | Режим |
|---|---|---|---|
| 🟢 зелёный | `COLLECT` | **B1** | Collector |
| 🟡 жёлтый | `MULTIPLIER` | **B3** | Multiplier frames |
| 🔴 красный | `2X BOARD` | **B2** | Двойная доска |

> ⚠️ Порядок в UI (зелёный-жёлтый-красный) **не совпадает** с порядком внутренних кодов.
> Маппинг подтверждён экспериментально через поле `activeBonusData`:
> `B1 → collector`, `B2 → doubleBoard`, `B3 → multipliers`.

Горшки визуально наполняются (описание AvatarUX: **5 стадий**; в атласе спрайтов
есть `collector_holder_1`, `1-1`, `1-2` и `colector_pile_green/yellow/red`).
Состояние отдаётся сервером в полях `bonusCounterData {b1,b2,b3}` и `progress {b1,b2,b3}`.

**Триггер:** когда падает бонус-символ, он **случайно** может активировать свой режим.
Несколько режимов могут активироваться **одновременно** — это ключевая особенность игры.

## 4. Бонус: Hold & Win

### 4.1 Общие правила

- Барабаны очищаются; внутри бонуса появляются **только** 4 типа объектов:
  **Coin**, **Jackpot**, **Collector**, **Multiplier frame**.
- **Респины: 3.** Любое новое попадание сбрасывает счётчик обратно на 3.
  Если за спин ничего не упало — счётчик уменьшается на 1. Раунд кончается на 0.
- Все упавшие символы **залипают** до конца раунда.
- Заполнение всей доски (15 ячеек) → **Grand Jackpot**.

Сервер отдаёт это в `freeSpins: {before, during, after, retrigger}`, где
`during = before − 1`, `after = 3` при `retrigger > 0` иначе `after = during`,
а `retrigger` = количество новых символов на этом спине.

### 4.2 Coin

Монета с случайным множителем **0.5× – 10×** ставки.
Три визуальных тира: бронза / серебро / золото (`number_coin_bronze/silver/gold`).

Наблюдавшийся набор номиналов при падении:
`0.5, 1, 1.5, 2, 2.5, 3, 4, 5, 6, 7, 8, 9, 10`. Доминирует **0.5×** (см. эмпирику).

### 4.3 Collector (режим B1, зелёный горшок)

> Collector symbol gathers all coin values and sums them up in a single cell.
> The coin symbols themselves remain in their space and their values can be collected again.

**Точная механика, восстановленная по покадровому разбору раунда:**

1. Collector падает в свободную ячейку.
2. Его значение = **сумма всех номиналов на доске**, включая монеты, упавшие
   **на этом же спине**.
3. Монеты **остаются на месте** со своими значениями.
4. Ячейка Collector'а становится обычной залипшей ячейкой со своим значением
   и сама участвует в последующих суммированиях.

Пример из живого раунда (значения в ×ставки):

```
до спина:      0.5 (r0c4), 0.5 (r2c3)                    сумма доски = 1.0
падает:        Coin 1.5 (r0c3) + Collector (r0c0)
Collector =    0.5 + 0.5 + 1.5 = 2.5
после спина:   2.5 (r0c0), 1.5 (r0c3), 0.5 (r0c4), 0.5 (r2c3)   сумма доски = 5.0
```

Именно это делает Collector самым «взрывным» режимом: каждый следующий коллектор
складывает предыдущие коллекторы **вместе с** исходными монетами.

### 4.4 Multiplier frames (режим B3, жёлтый горшок)

- Огненная рамка падает в **любую** позицию, значение **×2 – ×6**.
- Повторное попадание в **ту же** ячейку повышает рамку на **+1**
  (наблюдались ×7, ×8, ×9, ×11 — результат наложений).
- В **конце** раунда, если внутри рамки оказался символ, его значение умножается.
- Сервер держит это отдельной сеткой `multipliers` 5×3, где 1 = нет рамки.
- В атласе три уровня рамки: `symbol_frame_lvl1/lvl2/lvl3` + `*_multi_holder`.

### 4.5 Double Board (режим B2, красный горшок)

Открывается **вторая полная сетка 5×3**, которая крутится независимо.
Итого 30 ячеек. Заполнение **обеих** досок → **Grand дважды за один бонус**.
В ответе сервера вторая доска приходит в `board1Data` со своими
`board / cashPrizes / multipliers / features / freeSpins`.
В атласе: `machine_frame_bonus_divider`.

### 4.6 Джекпоты

Сервер отдаёт карту в каждом шаге: `jackpotPrizeMap`.

| Тир | Множитель | Как берётся |
|---|---|---|
| **Mini** | **15×** | символ-джекпот (зелёный чили) |
| **Minor** | **50×** | символ-джекпот (серебряный чили) |
| **Major** | **200×** | символ-джекпот (золотой чили) |
| **Grand** | **1000×** | **заполнение всей доски**, символа нет |

Несколько джекпот-символов могут выпасть одновременно.
Значения джекпотов **фиксированные**, не прогрессивные.

## 6. Как снять данные с игры заново

Демо доступно без авторизации. Клиент — обычный REST, без шифрования.

**Прямой запуск клиента:**
```
https://cdn-demo-eu.avatarux.app/3-chili-charms/index.html?game=3-chili-charms&wallet=demo&operator=demo&key=&server=https%3A%2F%2Fdemo-eu.avatarux.app&language=en&provider=avatarux&channel=desktop&rgs=avatarux-rgs
```

**RGS API** — база `https://demo-eu.avatarux.app`.
Заголовки: `Content-Type: application/json`, `x-session-id: <uuid4>`,
`Authorization: Bearer <token>`, плюс браузерный `User-Agent` и
`Origin: https://cdn-demo-eu.avatarux.app` (иначе **403**).

| Метод | Путь | Тело |
|---|---|---|
| POST | `/authenticate` | `{wallet:"demo", operator:"demo", key:"", provider:"avatarux", game:"3-chili-charms"}` |
| POST | `/game/info` | `{game, provider}` → `config / bets / betLimits` |
| POST | `/game/play` | `{game, provider, action, bet, complete:true}` |
| GET | `/game/cheats`, `/game/history`, `/game/replay`, `/game/recover` | |

`action` ∈ `main | ante | bonus-buy-1 | bonus-buy-2`.
`bet` — **полная стоимость спина**, не базовая ставка:
для BB1 при базовой 0.1 нужно `bet: 6`, для BB2 — `bet: 20`.

**Скорость:** одна последовательная сессия устойчиво даёт **~2.7 запроса/с**.
Параллельные потоки не ускоряют — только вызывают 429. Собирай последовательно, одним процессом.

**⚠️ Главная ловушка сбора данных.** Базовый спин, запустивший бонус, **не закрывает раунд**:
приходит `complete: false` и `next: ["fs1"]`. Пока раунд открыт, любой следующий
`/game/play` без продолжения возвращает **HTTP 400**, и сессия встаёт намертво.
Наивный сборщик из-за этого молча теряет **именно спины с триггером бонуса** —
и показывает нулевую частоту бонуса. Правильный цикл:

```python
st, d = play(action="main", bet=0.1)
while d["wager"].get("next"):
    d = play(action=d["wager"]["next"][0], bet=0.1, roundId=d["roundId"])
# только теперь раунд закрыт, можно делать следующий спин
```

### Формат ответа `/game/play`

```
wager.win                     итоговый выигрыш раунда в валюте
wager.data[]                  шаги раунда (в базе 1, в бонусе — по одному на респин)
  board            [5][3]     символы; в бонусе "CP" = ячейка с призом, null = пусто
  winLines[]                  сработавшие линии
  bonusCounterData {b1,b2,b3} накопленные чили по цветам
  progress         {b1,b2,b3} то же (визуальные горшки)
  bonusType                   в базе: "EMPTY" | "B1" | "B2 B3" | "B1 B2" ... —
                              через пробел перечислены цвета, получившие чили в этом спине;
                              в бонусе: "B1" | "B2B3" | "B1B2B3" — активные режимы
  next                        непусто -> раунд не закрыт, нужен вызов с action=next[0] и roundId
  isBonusTrigger              флаг запуска бонуса
  activeBonusData  {collector, doubleBoard, multipliers, isBonusBuy, isAnteGame}
  cashPrizes       {before,during,after}  [5][3] номиналы на доске
  multipliers      {before,during,after}  [5][3] сетка рамок, 1 = нет рамки
  freeSpins        {before,during,after,retrigger}  счётчик респинов
  features[]                  Coins / Multipliers / Collectors + позиции и значения
  jackpotPrizeMap  {mini:15, minor:50, major:200, grand:1000}
  accumulatedCashPrize        сумма на доске в ×ставки
  board1Data                  вторая доска (режим 2X BOARD), та же структура
  winCapReached               достигнут кап 15 000×
```

## 7. Эмпирика — измерено на живом RGS

Всё ниже получено прямыми вызовами демо-сервера, а не из документации.
Указывай размер выборки при использовании: часть цифр статистически шумная.

### 7.1 Композиция барабанов

Замер по частоте символов в видимом окне, **выборка 200 спинов = 3 000 ячеек**.

Барабаны спроектированы **двумя разными наборами лент**:

| | реел 1 | реел 2 | реел 3 | реел 4 | реел 5 |
|---|---|---|---|---|---|
| **WW** (wild) | **0.00 %** | 2.7 % | 4.8 % | 5.2 % | 3.5 % |
| H1 (жёлтый) | 10.0 % | 12.3 % | 16.5 % | 21.2 % | 20.3 % |
| H2 (красный) | 16.8 % | 17.0 % | 15.7 % | 15.8 % | 13.8 % |
| H3 (розовый) | 15.0 % | 19.2 % | 13.5 % | 18.0 % | 15.8 % |
| H4 (зелёный) | 6.8 % | **17.8 %** | 6.8 % | **15.2 %** | 5.8 % |
| L1 (A) | 12.5 % | **2.8 %** | 11.3 % | **2.0 %** | 12.2 % |
| L2 (K) | 4.3 % | **19.2 %** | 3.7 % | **16.7 %** | 1.7 % |
| L3 (Q) | 15.8 % | **4.5 %** | 14.2 % | **1.3 %** | 12.0 % |
| L4 (J) | 14.8 % | **2.2 %** | 10.0 % | **1.0 %** | 11.7 % |

Выводы, которые стоит перенести в свою математику:

1. **Wild никогда не появляется на 1-м барабане** (0 из 600 наблюдений).
   Вайлд живёт только на барабанах 2–5.
2. **Нечётные барабаны (1, 3, 5) и чётные (2, 4) используют разные ленты.**
   На чётных доминируют H4 и L2; на нечётных — L1, L3, L4.
   Это сознательно снижает частоту 5-в-ряд по низким символам.
3. Топовый символ H1 наоборот чаще встречается **справа** (реелы 4–5),
   что даёт больше «почти-выигрышей» и добивок по 3–4 символа.

### 7.2 Базовая игра

Выборка: **5 000 спинов**, ставка 0.1, один последовательный прогон, 0 ошибок.

| Метрика | Значение |
|---|---|
| Hit rate (любой выигрыш) | **27.7 %** — 1 спин из 3.6 |
| Медиана ненулевого выигрыша | **0.6× ставки** |
| Максимум без бонуса в выборке | 34× |
| RTP только с линейных выплат | **42.4 %** |

Базовая игра намеренно бедная: типичный выигрыш **меньше ставки**,
а линии дают меньше половины всего RTP. Остальное — бонус.

### 7.3 Накопление бонус-символов и триггер

`progress.b1/b2/b3` — счётчик собранных чили по цветам.
Поле `bonusType` в базовом спине перечисляет через пробел цвета, упавшие в этом спине
(`EMPTY`, `B1`, `B2 B3`, `B1 B2 B3`).

| Цвет | Код | Частота падения |
|---|---|---|
| 🟢 зелёный (Collector) | b1 | **14.96 %** спинов |
| 🔴 красный (2× Board) | b2 | **14.28 %** спинов |
| 🟡 жёлтый (Multiplier) | b3 | **14.74 %** спинов |
| хотя бы один | — | **32.4 %** спинов |

Сколько цветов за один спин: ноль — 67.6 %, один — 21.4 %, два — 10.6 %, три — **0.5 %**.
Прирост максимум **+1 на цвет за спин**.

#### Как именно срабатывает бонус

1. Бонус может сработать **только на спине, где реально упал чили этого цвета**.
2. Это **случайный ролл на каждом падении**, а не порог заполнения.
3. При срабатывании счётчик **этого цвета сбрасывается в 0**; два других сохраняются.

```
спин 488   b1=14  b2=65  b3=13   bt='B3'     <<< триггер MULT
спин 489   b1=14  b2=65  b3= 0   bt='EMPTY'      только b3 обнулился
```

**Вероятность срабатывания при падении чили** (58 триггеров на 2199 падений):

| Цвет | Триггеров / падений | P |
|---|---|---|
| 🟢 зелёный | 17 / 748 | 2.27 % |
| 🔴 красный | 17 / 714 | 2.38 % |
| 🟡 жёлтый | 24 / 737 | 3.26 % |
| **всего** | **58 / 2199** | **2.64 %** (95 % ДИ 1.97–3.31 %) |

**Итоговая частота бонуса: 1 раз в 102 спина** (0.98 %), 95 % ДИ — от 1 к 80 до 1 к 141.

Сходится арифметически: 14.7 % падений × 2.6 % × 3 цвета ≈ 1.1 % на спин.

#### Порога заполнения нет

Значение счётчика в момент срабатывания разбросано от **1 до 235**, медиана 22.
Медиана счётчика при любом падении — 29, то есть при срабатывании она даже **ниже**.
Если бы шанс рос по мере наполнения, было бы наоборот.

| Счётчик | Срабатываний / падений | P |
|---|---|---|
| 0–10 | 19 / 459 | 4.14 % |
| 10–25 | 13 / 515 | 2.52 % |
| 25–50 | 14 / 514 | 2.72 % |
| 50–100 | 9 / 419 | 2.15 % |

Тренд формально убывающий, но на 58 событиях доверительные интервалы перекрываются —
это скорее шум. **Рабочая модель: постоянный шанс ~2.6 % на каждое падение чили.**
«Пять стадий» из маркетинга AvatarUX — визуальная подача наполнения горшка,
на вероятность она не влияет (что прямо написано и в правилах игры:
*«visual elements … do not influence the outcome … Visual changes do not affect RTP»*).

### 7.4b Бонус при естественном триггере (не покупка)

Выборка: **49 бонусов**, пойманных за 5 000 базовых спинов и доигранных до конца.

| Комбинация режимов | Доля | для сравнения BB1 |
|---|---|---|
| только MULTIPLIER | 32.7 % | 26.2 % |
| только COLLECT | 26.5 % | 23.5 % |
| только 2× BOARD | 22.4 % | 20.8 % |
| 2×BOARD + MULTIPLIER | 10.2 % | 10.5 % |
| COLLECT + MULTIPLIER | 6.1 % | 3.0 % |
| COLLECT + 2×BOARD | 2.0 % | 7.5 % |
| **все три** | **0 %** | **8.5 %** |
| — один режим | **81.6 %** | 70.5 % |
| — два режима | 18.4 % | 21.0 % |

**Платный бонус даёт заметно лучшие шансы на комбинацию, чем бесплатный.**
Тройной режим за 49 естественных триггеров не выпал ни разу — при доле BB1 в 8.5 %
ожидалось бы ~4, так что доля в бесплатном бонусе точно ниже, хотя и не обязательно нулевая.

| Метрика | Значение |
|---|---|
| Средний выигрыш в выборке | 31.9× ставки |
| Медиана | 31.5× |
| Максимум в выборке | 76× |
| Респинов на раунд | в среднем 14.8, максимум 23 |
| Раундов ≥ 50× | 16.3 % |

⚠️ **Хвост не выбран.** Ни одного бонуса ≥ 100× за 49 раундов, тогда как в BB1
(n = 400) таких 11.8 %, а ≥ 1000× — 0.5 %. Поэтому 31.9× — это заниженная оценка.

Восстановим истинное среднее из баланса RTP:
`96.193 % − 42.43 % (линии) = 53.76 %` приходится на бонус,
при частоте 1 к 102 это **≈ 55× ставки на бонус**.
Это почти совпадает со средним BB1 (57.6×) и означает, что **цена BB1 в 60× честная** —
покупка примерно равна ожиданию бесплатного бонуса.

### 7.4c Проверка сходимости RTP

| Источник | Реализованный RTP | Выборка |
|---|---|---|
| Только линии | 42.43 % | 5 000 спинов |
| + бонусы | 73.72 % | 49 бонусов |
| Теория | **96.193 %** | — |

Недобор в ~22 п.п. — целиком следствие невыбранного хвоста бонуса.
**Вывод для баланса: около 56 % всего RTP лежит в бонусе, и львиная доля этого —
в редких длинных раундах.** Это и есть причина метки «Super High» волатильности.

### 7.5 Распределения внутри бонуса

Номиналы **множитель-рамок** (частота наблюдений, режим MULTIPLIER):

| ×2 | ×3 | ×4 | ×5 | ×6 | ×7+ |
|---|---|---|---|---|---|
| ~54 % | ~29 % | ~11 % | ~3.7 % | ~2 % | ~0.9 % |

`×7` и выше получаются только наложением рамок на одну ячейку (+1 за попадание).

Номиналы **монет** при падении: `0.5, 1, 1.5, 2, 2.5, 3, 4, 5, 6, 7, 8, 9, 10`.
Доминирует **0.5×** с большим отрывом — крупные монеты редки.
Значения `15 / 50 / 200` в сетке призов — это символы джекпотов Mini / Minor / Major.

## 8. Как это реализовать

Разбор для переноса в собственную игру.

### 8.1 Что делает игру играбельной

Ядро — **не барабаны**, а бонус. Базовая игра здесь намеренно скучная
(hit rate 26 %, медианный выигрыш 0.6× ставки) и служит трём целям:

1. **насос для горшков** — ~32 % спинов дают хотя бы один чили, игрок видит прогресс;
2. **редкие вспышки** от стакнутых вайлдов;
3. **ожидание** — три горшка наполняются с разной скоростью, и игрок постоянно
   видит, какой ближе к срабатыванию.

Если копируешь механику, **не облегчай базу** — иначе бонус перестанет быть событием.

### 8.2 Структура состояния

```ts
type BonusMode = 'collector' | 'multiplier' | 'doubleBoard'

type Cell = {
  kind: 'empty' | 'coin' | 'jackpot' | 'collector'
  value: number          // ×ставки; для джекпота 15 | 50 | 200
  frame: number          // множитель рамки, 1 = нет рамки
}

type BonusState = {
  modes: Set<BonusMode>
  boards: Cell[][][]     // 1 или 2 доски 5×3
  respins: number        // стартует с 3
  accumulated: number    // сумма всех value на досках
}
```

### 8.3 Цикл респина (псевдокод)

```
respins = 3
while respins > 0:
    landed = rollNewSymbols(freeCells)     # монеты / джекпоты / коллекторы / рамки
    for sym in landed:
        place(sym)
        if sym.kind == 'collector':
            # ВАЖНО: сумма считается ПОСЛЕ размещения всех монет этого спина
            sym.value = sumOfAllValuesOnBoard()
            # монеты НЕ убираются
    respins = landed.isEmpty ? respins - 1 : 3
    if boardIsFull(): awardGrand(1000x); break     # для каждой доски отдельно

# в самом конце раунда
for cell in allCells:
    if cell.frame > 1: cell.value *= cell.frame
payout = min(sumOfAllValues(), 15000)
```

Три тонкости, которые легко упустить:

- **Collector суммирует и монеты, упавшие в том же спине** — иначе он слабее оригинала.
- **Монеты не расходуются**: тот же 0.5× может быть собран пятью коллекторами подряд.
- **Рамки применяются один раз в конце**, а не на каждом респине.

### 8.4 Где лежит риск при копировании

| Решение оригинала | Зачем | Что будет, если убрать |
|---|---|---|
| Collector не удаляет монеты | источник экспоненциального роста | бонус станет линейным и скучным |
| Рамки применяются в конце | защищает от двойного умножения | RTP улетит вверх |
| Grand = заполнение доски, не символ | делает Double Board осмысленным | второй режим потеряет ценность |
| Кап 15 000× обрывает раунд | ограничивает хвост | неограниченный риск |
| Медиана BB2 < цены покупки | покупка не должна быть «читом» | покупка сломает экономику |

### 8.5 Ориентиры для баланса

Замеренные значения, на которые можно опереться при своей математике:

**Темп**
- Бонус — **1 раз в ~100 спинов** (шанс 2.6 % на каждое падение чили, чили падает в ~15 % спинов на цвет).
- Хотя бы один чили — **треть всех спинов**: игрок постоянно видит движение.
- Респинов в бонусе — **~15**, до ~30 в длинных.

**Деньги**
- Линии дают только **~44 %** RTP, бонус — **~56 %**.
- Средний бонус ≈ **55× ставки**; медиана заметно ниже среднего (хвост тяжёлый).
- Базовый hit rate **~28 %**, медианный выигрыш **0.6× ставки** — то есть
  большинство «выигрышей» в базе убыточны. Так и задумано.

**Режимы**
- Бесплатный бонус: один режим **82 %**, два **18 %**, три — почти никогда.
- Покупка BB1: один **70 %**, два **21 %**, три **8.5 %**.
- Покупка BB2: три режима **всегда**.
- Цена BB1 (60×) ≈ ожиданию бесплатного бонуса (~55×) — покупка честная, не чит.
- Медиана BB2 (105×) **вдвое ниже** цены (200×): премиум-покупка тоже не ломает экономику.

**Джекпоты** — фиксированные, не прогрессивные: 15 / 50 / 200 / 1000.

**Ante** ×1.5 даёт заявленный ×2 шанс бонуса и +0.08 п.п. RTP — по EV почти нейтрален,
это регулятор темпа, а не выгодная опция.

## 10. Что осталось непроверенным

Честный список пробелов — чтобы в следующей сессии не выдавать догадки за факты.

1. **Хвост распределения бонуса при естественном триггере.** За 49 бонусов не поймано
   ни одного ≥ 100×. Истинное среднее (~55×) восстановлено из баланса RTP, а не измерено.
   Нужно ~500 естественных бонусов ≈ 50 000 базовых спинов ≈ 5 часов сбора.
2. **Доля тройного режима при бесплатном триггере** — 0 из 49. Точно ниже, чем 8.5 % у BB1,
   но верхняя граница не установлена.
3. **Частота джекпотов Mini / Minor / Major и заполнения доски (Grand)** — не посчитана.
   Данные для этого есть в сырых ответах бонус-раундов, нужен отдельный разбор
   `cashPrizes.after` на значения 15 / 50 / 200 и на полное заполнение.
4. **Точное распределение номиналов монет при падении.** Снималось смешанно с залипшими
   ячейками, поэтому доли смещены в пользу мелких номиналов. Правильно брать только
   `features[name=="Coins"].symbolData[].value`.
5. **Композиция барабанов** измерена на 200 спинах (3 000 ячеек). Вывод «wild не бывает
   на 1-м барабане» опирается на 0 из 600 — вероятен, но не доказан. Разделение лент
   на чётные/нечётные барабаны видно уверенно.
6. **Ante не проверен эмпирически** — «×2 шанс бонуса» взято из UI, не измерено.
7. **Слабый убывающий тренд** вероятности срабатывания по мере роста счётчика
   (4.1 % → 1.0 %) — на 58 событиях неотличим от шума. Если понадобится точность,
   нужна выборка на порядок больше.
8. **Динамика и тайминги анимаций** не сняты: клики по canvas в headless-браузере
   не доходят до PixiJS. Нужен обычный браузер вручную.

### Как закрыть пробелы

Рабочий скрипт сбора — `final.py` в скрэтчпаде сессии, сырые данные —
`trig.jsonl` (5 000 базовых спинов + 49 бонусов), `bb1.jsonl` (400), `bb2.jsonl` (150).

Ключевые грабли, на которые я уже наступил, — все описаны в разделе 6:
незакрытый раунд после триггера, отсутствие `bet` в запросе продолжения,
обязательные браузерные заголовки. Наивный сборщик без этого показывает
**нулевую частоту бонуса** и выглядит правдоподобно.
